# Архитектурные решения (ADR)

Каждое решение, которое дорого откатывать, записано здесь. ADR — это не отчёт: это
контракт. Код, противоречащий принятому ADR, считается дефектом, пока ADR не заменён
новым.

## Статусы

| Статус | Значение |
|---|---|
| `proposed` | предложено, ещё не действует |
| `accepted` | действует; код обязан соответствовать |
| `superseded by NNNN` | заменено более новым решением |
| `rejected` | рассмотрено и отклонено; причина в тексте |

Подтип остаётся идентичностью (категория, лог), но с карточки уходит; подпись и поиск читают одно поле (дополняет ADR-0010 §1, ADR-0015, ADR-0017, ADR-0023 §3, ADR-0035) | accepted |
| [0044](0044-event-change-resets-editor-watches.md) | **Смена события event controller — это сброс**: привязки, добавленные редактором, удаляются, а не проигрываются в новый компонент (отменяет §3 п.5 ADR-0018). Чтобы это было видно и при закрытом редакторе, идентификатор события (`UniqueSelectionId`) записывается **вместе со списком** в одно значение (`"e12 34 56"`), а значение прежней версии без заголовка не удаляется, а помечается текущим событием. Ноль с любой стороны — «неизвестно», не «другое событие»; `ControllerState.WatchEventId` удалён (дополняет ADR-0017 §6) | accepted |
| [0045](0045-hotkey-opens-editor-from-cockpit.md) | **Клавиша M открывает схему из кокпита**: второй вход в тот же экран (`VgsEditorScreen.OpenFor`), опрос `IsNewKeyPressed` раз в тик из сессионного компонента (привязку мод зарегистрировать не может — `IMyInput` только читает). Работает, только если игрок управляет `IMyCockpit` и клавиатурой не владеет никто другой: не чат (`ChatEntryVisible`), не игровой экран (`ActiveGamePlayScreen`), не терминал (`GetCurrentScreen`, который в `ActiveGamePlayScreen` **не** входит), не модификатор. Клавиша — константа в самом типе, а не в `VgsConstants` (модель компилируется офлайн-шлюзом без `MyKeys`) | accepted |
| [0046](0046-curved-connection-lines.md) | **Линия связи — плавная кривая толщиной ровно 2 px**, линия отслеживания — **точки** 2 px с шагом 4 px. Маршрут остаётся ортогональным (`EdgeRouting.Build`/`BuildSelfLoop` — его же потребляет труба), а рисуется скруглённый путь (`EdgeRouting.Round`): прямая до середины первого отрезка, квадратичный Безье до середины каждого следующего с углом маршрута в контрольной точке, прямая в цель. Растеризация — в пикселях safe-области тем же преобразованием, что и границы гридов (`PixelTransform.FromClientTransform`, `Ui/LineRaster`), обходом по пиксельным столбцам со склейкой с пределом роста, толщина `LinePixels` не зависит от зума; `VgsScreenDraw.Segment`/`SegmentDashed` и `EdgeRouting.BuildDashes` удалены (отменяет §6 ADR-0010, пунктир §5 ADR-0017) | accepted, §2 (сплошная линия) superseded by 0047 |
| [0047](0047-dotted-connection-lines.md) | **Связь рисуется плотными точками: 2 px через 1 px** (период 3 px), линия отслеживания остаётся 2 px через 2 px. Причина — у API нет антиалиасинга: сплошная линия с жёстким краем читалась как «толще 2 px», а пиксельные зазоры глаз усредняет с линией и она читается легче. Вес не меняется (точка всё те же 2 × 2 px), меняется только непрерывность; два вида линии различаются ритмом, а не только цветом. Один растеризатор на оба вида — `LineRaster.Dotted` с ритмом в параметрах; `LineRaster.Solid`, `VgsScreenDraw.PathPixels`/`PathDottedPixels` заменены одним `VgsScreenDraw.PathDots` (заменяет §2 ADR-0046, уточняет его §3) | accepted |
