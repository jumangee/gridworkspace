> **Этот ADR неверен и заменён [ADR-0027](0027-clipboard-is-own-buffer-only.md).**
>
> Мод перестал загружаться: игра отвергла `VRage.IVRageSystem`, `VRage.IVRagePlatform` и
> `VRage.MyVRage` как `is prohibited`. Ошибка была в выводе «тип лежит в разрешённом пространстве
> имён `VRage` ⇒ мод может его использовать»: для **корневого** `VRage` это не так, типы там
> перечислены поимённо. Хуже того, шлюз `check-whitelist.ps1` подтвердил неверный вывод, потому
> что его декодер терял цель записи вайтлиста (`ModApi` против `Ingame`) — см. ADR-0027 §3.
>
> Текст ниже оставлен как есть, чтобы была видна причина замены. Действующая норма — ADR-0027.

## Context

### 1. Что было записано и почему это оказалось неверно

ADR-0024 §Context 3 утверждал: «у мода нет способа прочитать системный буфер обмена», и на этом
строил §Decision 3 (вставка только из собственного буфера) и §Consequences («жёсткий предел API»).
Проверка была неполной в трёх местах:

| Что утверждалось | Что на самом деле | Чем проверено |
|---|---|---|
| `VRage.Platform.Windows.Forms.MyClipboardHelper` — internal | тип **public** (`IsPublic = True`, `IsAbstract && IsSealed`), и у него есть **public static** `GetClipboardText()` | рефлексия по `VRage.Platform.Windows.dll` |
| поэтому прочитать нельзя | нельзя **прямо**: пространство `VRage.Platform.Windows.Forms` не в вайтлисте | пробная сборка + `check-whitelist.ps1 -Assembly` → `namespace ... is not whitelisted` |
| других путей нет | **есть**: `VRage.MyVRage.Platform` → `IVRagePlatform.System` → `IVRageSystem.Clipboard` — все три в разрешённом `VRage` | `check-whitelist.ps1` на пробной сборке → `WHITELIST OK` |

Первопричина ошибки — в инструменте, а не только во мне: `dump-se-api.ps1` печатает
`DeclaredOnly`-члены из предзагруженного списка сборок, и `VRage.Platform.Windows.dll` в этот
список не входит. Отсутствие члена в дампе было прочитано как отсутствие члена в игре. Это
записано отдельным правилом ниже.

### 2. Проверенная цепочка чтения

[ПРОВЕРЕНО] `tools/dump-se-api.ps1 -Types 'VRage.MyVRage','VRage.IVRagePlatform','VRage.IVRageSystem'`:

```csharp
public static IVRagePlatform Platform { get; set; }   // VRage.MyVRage
public IVRageSystem System { get; }                   // VRage.IVRagePlatform
public String Clipboard { get; set; }                 // VRage.IVRageSystem — getter AND setter
```

[ПРОВЕРЕНО] `tools/dump-se-il.ps1 -Assembly 'VRage.Platform.Windows.dll'
-Type 'VRage.Platform.Windows.Sys.MyWindowsSystem' -Method 'get_Clipboard'`:

```il
call VRage.Platform.Windows.Forms.MyClipboardHelper::GetClipboardText
ret
```

а `GetClipboardText` — единственный `call System.Windows.Forms.Clipboard::GetText`. То есть
геттер не заглушка: это настоящая читка системного буфера.

[ПРОВЕРЕНО] `tools/dump-se-il.ps1 … -Method 'set_Clipboard'` — `call …::SetClipboard`, тот же
маршрут, что и раньше использовался для записи, только теперь через разрешённое пространство имён.

### 3. Почему собственный буфер остаётся

Чтение системного буфера может отказать по причинам вне мода: `Clipboard.GetText()` бросает
`ThreadStateException`, если вызывающий поток не STA, и `ExternalException`, когда буфер
удерживает другой процесс. Оба случая на десктопе обычны. Поэтому:

```
вставка: системный буфер → (если не читается) собственный буфер → (если пуст) ничего
копирование: собственный буфер (всегда) + системный буфер (best effort)
```

Собственный буфер пишется **первым и безусловно**, поэтому копирование всегда делает вставку
работающей внутри редактора, даже если системная запись отказала.

## Decision

### 1. Читать и писать через `IVRageSystem.Clipboard`

Обе операции идут через `VRage.MyVRage.Platform.System.Clipboard`. Прямой вызов
`VRage.Platform.Windows.Forms.MyClipboardHelper` остаётся запрещённым — не потому, что тип
недоступен, а потому, что его **пространство имён** не в вайтлисте, и шлюз это ловит.

Обе операции обёрнуты в `try/catch` с `VgsLog.Throttled`: это Win32-вызовы, которые штатно
бросают исключения при занятом буфере, и превращать обычное состояние десктопа в ошибку в логе
нельзя.

### 2. Собственный буфер — запасной путь, а не основной

`TextClipboard.PasteText` читает системный буфер при каждом обращении (не кэширует: другое
приложение могло сменить содержимое между двумя вставками), и откатывается на собственный
буфер, если системный не прочитался или пуст.

**Но одного «системный первым» недостаточно, и это была ошибка в первой редакции.** Если запись
в системный буфер отказала, системный буфер хранит *предыдущий* текст, а чтение при этом может
удаться — и тогда Ctrl+V вставит не то, что игрок только что вырезал, а то, что было скопировано
до этого. Поэтому `Copy` запоминает неудачу в `_systemWriteFailed` **и** то, что в этот момент
лежало в системном буфере (`_staleSystemText`), а `PasteText` при этом флаге принимает системный
текст только если он **отличается** от запомненного.

Случай достижим двумя путями: исключение при записи (буфер удерживает другой процесс) и
`MyVRage.Platform == null` на очень раннем этапе — второй особенно неприятен, потому что
происходит **без исключения** и потому не виден в логе.

**Флаг не залипает.** Если бы он снимался только следующей удачной записью, одна неудачная
копия отключала бы вставку чужого текста до конца сессии — молча: игрок копирует имя блока в
блокноте, жмёт Ctrl+V и получает свой старый запрос без всякого объяснения. Сравнение с
запомненным значением различает два случая: буфер всё ещё тот же (вставлять нельзя) и буфер
сменился, значит блокировка прошла (вставлять можно, и флаг снимается).

**Если при отказе записи не удалось прочитать и буфер** (одна блокировка `OpenClipboard` рушит и
запись, и чтение — то есть это вероятная пара, а не редкая), запоминается null, и тогда до
следующей удачной копии работает только собственный буфер. Это сознательно консервативно: null
означает «сравнивать не с чем», а «сравнивать не с чем» обязано склоняться в сторону своего
буфера — иначе вставился бы ровно тот старый текст, ради предотвращения которого всё и делалось.

**Пустая строка и null — разные вещи.** Пустое запомненное значение означает «буфер был прочитан
и был пуст», поэтому любой появившийся позже непустой текст — заведомо новый, и он принимается.
Null означает «неизвестно» и уходит в свой буфер.

**Если другое приложение выставит тот же самый текст**, он будет отвергнут как устаревший.
Это консервативно и неотличимо от настоящего устаревания, поэтому принято без дополнительной
логики: в худшем случае игрок получит свой буфер вместо идентичной строки извне.

`HasText` удалён: у него не было ни одного вызова, а свойство, читающее системный буфер,
однажды вызванное из пути отрисовки, стало бы нарушением R010 и обращением к ОС каждый кадр.

### 2а. Побочное следствие: замороженный счётчик кадров

Пока разбирался с кареткой, выяснилось, что `VgsSession.Frame` **не растёт, пока открыт
редактор**: экран ставит игру на паузу, а `UpdateAfterSimulation` на паузе вызывается только у
компонентов с `UpdateOnPause`, которого у мода нет (цепочка проверена по IL, см.
[api-terminal-search.md](../01-research/api-terminal-search.md) §2.5).

Это тот же класс дефекта, что и «каретка не мигает», и он задевал не только каретку: мигание
каретки, истечение предупреждений, вспышку отказа отслеживания, троттлинг обновления схемы,
троттлинг сохранения вида, повтор иконочных текстур и троттлинг лога. Таблица «что стояло на
замершем счётчике → как проявлялось» и **нормативное правило** вынесены в
**[ADR-0026](0026-clocks-in-the-mod.md)**: норма, спрятанная внутри ADR про буфер обмена, не
будет найдена тем, кто через полгода добавит кулдаун, — а это ровно то, из-за чего дефект и
повторился в трёх местах.

`UpdateOnPause` у сессионного компонента **не** выставлен сознательно: это заставило бы весь мод
(обновление схемы, сверку отслеживания, запись состояний) работать в приостановленной сессии и
в открытом меню паузы — изменение куда шире, чем нужно для этого дефекта.

### 3. Правило про инструменты (причина ошибки, а не её симптом)

**«Нет в дампе» ≠ «нет в игре».** `dump-se-api.ps1` печатает только предзагруженные сборки
(`$preload` в скрипте) и только `DeclaredOnly`. Утверждение «тип X не имеет члена Y» можно делать
только после `find-se-type.ps1` (в какой сборке живёт тип) и `dump-se-api.ps1 -Types X
-IncludeNonPublic` по **этой** сборке, либо рефлексией напрямую. Утверждение «моду это
недоступно» требует ещё и `check-whitelist.ps1` на **пробной сборке**, которая это вызывает, —
компиляция сама по себе ничего не доказывает (см. [ADR-0008](0008-mod-screen-api.md)).

Это правило действует для всех будущих решений, а не только для буфера.

### 4. Что осталось запрещено

- `Sandbox.Graphics.GUI.MyGuiControlTextbox` — по-прежнему недоступен, вывод ADR-0024 §Context 2
  в силе (проверено: `Sandbox.Graphics` отсутствует в 57 разрешённых пространствах).
- Прямая ссылка на `VRage.Platform.Windows.*` — недоступна по пространству имён.

## Alternatives

| Вариант | Почему отклонён |
|---|---|
| Оставить как было (только собственный буфер) | Основано на ложном факте: системный буфер читается. Игрок, скопировавший имя блока в блокноте, зря не смог бы его вставить |
| Читать напрямую `MyClipboardHelper.GetClipboardText()` | Пространство имён не в вайтлисте → мод не загрузится |
| Кэшировать прочитанное | Другое приложение может сменить буфер между двумя вставками; игрок получил бы старое без объяснения |
| Убрать собственный буфер совсем | Системное чтение штатно отказывает (STA, занятый буфер); без запасного пути Ctrl+V иногда «не работает» без причины |
| Записать ADR-0024 как есть и пометить «не проверено» | Факт проверяем и проверен; оставлять в контракте неверное утверждение нельзя |

## Consequences

Что становится легко:

- вставка работает с текстом, скопированным в любом другом приложении;
- копирование работает наружу (как и раньше);
- оба направления проходят один и тот же шлюз, и оба разрешены.

Чем платим:

- **два внешних вызова на одно нажатие** Ctrl+V, оба могут бросить исключение — отсюда
  `try/catch` и троттлинг в логе;
- **поведение зависит от состояния ОС**: занятый буфер означает откат на собственный. Это
  записано в приёмке, чтобы «иногда не вставляется чужое» не считалось дефектом мода;
- **`MyVRage.Platform` может быть null** на очень раннем этапе; обе операции это учитывают, и
  запись в этом случае помечается неудачной, чтобы следующая вставка не прочитала старое;
- **если главный поток игры окажется MTA**, каждое чтение бросит `ThreadStateException`, в лог
  уйдёт одна троттлированная строка, и вставка молча останется «только своим». Это
  load-bearing неизвестность, вынесенная в приёмку (пункт 1), а не в «работает».

Известные пределы, принятые сознательно:

- **Суррогатные пары.** Модель `TextEditor` посимвольная, поэтому Backspace/Delete и обрезка по
  лимиту длины могут разрезать пару UTF-16 (вставленный эмодзи) на половину. Для имён блоков это
  практически недостижимо, а UTF-16-осведомлённое удаление — отдельная задача; половина решения
  здесь была бы хуже, чем названный предел;
- **Ctrl+C без выделения копирует весь запрос**, поэтому Ctrl+C, Ctrl+V продублирует его. Это
  следует из выбранного «копировать всё, если ничего не выделено»; отменяется вручную —
  выделить дубликат и нажать Backspace (в поле нет undo, и это записано, а не умолчано).
  Стандартное поле ведёт себя иначе.

Если окажется, что `IVRageSystem.Clipboard` на клиенте возвращает пустую строку всегда (например,
платформа подменена), откат уже есть: собственный буфер продолжает работать, и меняется одна
ветка в `TextClipboard`.

## Verification

```powershell
# 1. Тип публичный и имеет чтение — РЕФЛЕКСИЕЙ, не дампом.
#    dump-se-api.ps1 здесь бесполезен: он печатает DeclaredOnly-члены предзагруженных
#    сборок, а VRage.Platform.Windows.dll в этот список не входит и вернёт
#    "No public type matched ... (is it internal, or in an assembly not preloaded?)".
#    Это не «члена нет», это «сборка не предзагружена» — см. §Decision 3.
$bin = 'H:\SteamLibrary\steamapps\common\SpaceEngineers\Bin64'
$resolver = [System.ResolveEventHandler] {
    param($s, $e)
    $name = ($e.Name -split ',')[0]
    $path = Join-Path $bin "$name.dll"
    if (Test-Path $path) { return [System.Reflection.Assembly]::LoadFrom($path) }
    return $null
}
[System.AppDomain]::CurrentDomain.add_AssemblyResolve($resolver)
$a = [System.Reflection.Assembly]::LoadFrom((Join-Path $bin 'VRage.Platform.Windows.dll'))
$t = $a.GetType('VRage.Platform.Windows.Forms.MyClipboardHelper')
"public={0}" -f $t.IsPublic
$t.GetMembers('Public,NonPublic,Static,DeclaredOnly') | ForEach-Object { '  ' + $_.ToString() }

# Ожидаемо: public=True, SetClipboard(String) и GetClipboardText().

# 2. Цепочка через разрешённое пространство имён
& .\tools\dump-se-api.ps1 -Types 'VRage.MyVRage','VRage.IVRagePlatform','VRage.IVRageSystem'
& .\tools\dump-se-il.ps1 -Assembly 'VRage.Platform.Windows.dll' `
    -Type 'VRage.Platform.Windows.Sys.MyWindowsSystem' -Method 'get_Clipboard'

# 3. Шлюзы проекта: 158 ссылок, все разрешены
& .\tools\verify-compile.ps1     # COMPILE OK
& .\tools\check-whitelist.ps1    # WHITELIST OK
& .\tools\review-check.ps1       # без находок
& .\tools\offline-check.ps1      # OFFLINE OK
```

Человек в игре:

1. Скопировать имя блока в блокноте Windows, открыть схему, Ctrl+V в поле поиска — текст
   вставился.
2. Ctrl+C в поле, вставить в блокнот — текст вставился.
3. Ctrl+X с выделением — выделение исчезло, Ctrl+V вернул его.
4. Ctrl+X **без** выделения — поле не опустело (стандартное поведение поля).
5. Вставка многострочного текста из блокнота — вставилась одной строкой, переводы строк убраны.
6. Если другое приложение удерживает буфер — вставка не падает и не пишет ошибку в чат; в логе
   строка `[VGS]` с троттлингом, и она **повторяется с интервалом**, а не появляется один раз за
   весь сеанс (троттлинг переведён на попытки, ADR-0026 §3).
