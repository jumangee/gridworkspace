# 0003. Слои и правило «Ui не читает мир при рисовании»

- Status: accepted
- Date: 2026-11-18
- Supersedes: —
- Corrected: 2026-11-22 (по ревью ADR-0021) — §Decision в части «`Ui → Game` **только для
  вызова обновления**» **отменяется**: формулировка была уже́ кода с самого начала. `Ui` зовёт
  `Vgs.Game` из **действий пользователя** (`ToolbarWriter` при создании и удалении связи,
  `NodeStateStore` при перетаскивании карточки, `EventControllerProbe` при отслеживании,
  `TerminalJump` при переходе в терминал), и это не нарушение слоя, а его смысл: экран не умеет
  писать в мир, поэтому любая запись — вызов `Game` из обработчика ввода. Инвариант, который
  действительно проверяется, другой и записан ниже в §Decision: **`Ui` не читает и не пишет мир
  из пути отрисовки** — только из обработчиков ввода, обновления и открытия экрана. Основание
  правки — [`docs/review/joint-review.md`](../review/joint-review.md) §2 («расхождение с документом,
  который устарел, а решения не менялись — архитектор просто обновляет документ»); отдельный ADR не
  нужен, потому что решение не меняется, а формулировка догоняет код, который был таким с самого
  начала. Правку вносит архитектор, как требует [`docs/05-agents.md`](../05-agents.md) §2.
  Расхождение замечено при добавлении `TerminalJump` (ADR-0021), но существовало раньше.

## Context

Мод живёт внутри игрового цикла. `Draw()` вызывается каждый кадр, `UpdateAfterSimulation`
— каждый тик. Обращение к живому блоку (`IMyTerminalBlock`) — это поиск в мире, который
дороже любой арифметики, и он может упасть, если блок уничтожен между кадрами.

Кроме того, запуск игры — самая дорогая операция в цикле разработки. Всё, что можно
проверить без неё, должно быть проверяемо без неё.

## Decision

Четыре слоя с односторонними зависимостями:

```
Vgs.Core  →  ничего игрового, кроме чтения фасада сессии
Vgs.Model →  НЕ ссылается на Sandbox.*, VRage.Game.ModAPI, VRage.ModAPI
Vgs.Game  →  единственное место, где читаются и пишутся живые сущности
Vgs.Ui    →  читает только снимок модели; никогда не читает мир при рисовании
```

Разрешённые зависимости: `Ui → Model`, `Ui → Game` (из обработчиков ввода, обновления и открытия
экрана — для чтения мира, записи в него и обновления снимка), `Game → Model`, `Game → Core`,
`Ui → Core`, `Model → (ничего)`, `Core → (ничего)`.

**Граница проходит по вызову, а не по стрелке.** Стрелка `Ui → Game` разрешена всегда; запрещён
вызов `Vgs.Game` из метода, который игра зовёт каждый кадр ради картинки (`OnDraw` и всё, что он
зовёт). Причина — та же, из-за которой слои и появились: обращение к живому блоку в `Draw` это
поиск в мире на каждый кадр и падение, если блок уничтожен между кадрами. Поэтому `Vgs.Ui`
получает данные для рисования из снимка `GridGraph`, а всё, что трогает мир, делает в
`OnHandleInput`/`OnUpdate`/`OnOpened` — там, где это происходит по действию игрока, по таймеру или
один раз при открытии экрана (в `OnOpened` читается `IMyCubeGrid.CustomName` для шапки).

`VRageMath` разрешён в `Model`: это библиотека значимых типов (`Vector2`, `Vector3I`) без
доступа к сущностям. Переписывать векторы ради формальной чистоты было бы хуже.

Правило для `Ui`: данные для отрисовки приходят из `GridGraph`, обновляемого по таймеру
(`RefreshIntervalFrames`), а не из игры на каждом кадре. Строки, отображающие редко
меняющиеся значения, кэшируются и пересобираются при изменении значения.

## Alternatives

| Вариант | Почему отклонён |
|---|---|
| Один слой, обращение к блокам по месту | Невозможно проверить логику без игры; просадки кадров на больших гридах |
| Отдельный поток для чтения грида | Игровые API не потокобезопасны; маршалинг сложнее выигрыша |
| Кэш в `Vgs.Ui` вместо модели | Дублирование состояния и рассинхронизация с моделью |

## Consequences

- Легко: `Vgs.Model` тестируется и ревьюится без запуска игры; отрисовка предсказуема по
  стоимости.
- Трудно: на границе `Game → Model` нужны конвертеры; новые данные для UI требуют
  протаскивания через снимок.
- Запрещено: `using Sandbox.*` и `using VRage.Game.ModAPI` в `Model`; чтение
  `IMyTerminalBlock`/`IMyCubeGrid` из методов `Draw*`.
- При ошибке страдает один слой.

## Verification

```powershell
pwsh -File tools/review-check.ps1 -Rules R001,R010
```

`R001` ловит игровые `using` в `Model`, `R010` — аллокации и LINQ в методах `Draw*`.
Оба должны давать 0 находок.
