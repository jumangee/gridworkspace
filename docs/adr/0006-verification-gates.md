# 0006. Шлюзы: компиляция, вайтлист, статическое ревью и офлайн-проверки

- Status: accepted
- Date: 2026-11-19
- Supersedes: —

## Context

Игра сама компилирует исходники мода, поэтому обычная сборка ничего не доказывает:
ошибка обнаруживается только при запуске игры. Это делает цикл обратной связи самым
дорогим местом проекта.

Проверено на этой машине: Roslyn из установленного .NET SDK можно запустить против
сборок игры, и он воспроизводит условия внутриигровой компиляции (C# 7.3, .NET Framework
4.x, `-nostdlib+`). Без ссылки на `netstandard.dll` при этом возникает около сотни ложных
ошибок вида «The type 'Object' is defined in an assembly that is not referenced».

Второй класс проблем — механический: нарушение слоёв, `async/await`, `MyLog` напрямую,
незащищённый вход из игрового цикла, аллокации в `Draw`. Их находит человек, но находит
нестабильно.

## Decision

Четыре шлюза, все обязательные:

1. **`tools/verify-compile.ps1`** — компиляция против реальных сборок игры. Печатает
   `COMPILE OK` или список ошибок. Это доказательство вызываемости, не поведения.
2. **`tools/check-whitelist.ps1`** — сверка ссылок мода с IL-вайтлистом скриптов игры
   (добавлен вместе с [ADR-0008](0008-mod-screen-api.md)): компиляция доказывает
   вызываемость, а не допустимость.
3. **`tools/review-check.ps1`** — статические правила R001–R010 с уровнями
   ERROR/WARNING/INFO. Ненулевой код возврата при наличии ERROR.
4. **`tools/offline-check.ps1`** — офлайн-проверки **поведения**: собирает
   `tests/OfflineChecks.cs` вместе с `Vgs.Model`, `PortGeometry` и `EdgeRouting`, не
   поднимая игру, и проверяет свойства, от которых зависит картинка и граф: слоты портов
   без дыр, fan-in даёт одну полосу на вход, fan-out — отдельную на выход, входящий стакан
   не пересекается с исходящим, точки совпадают с hit-test, маршрут ортогонален и приходит
   в цель слева.

Шлюз 4 добавлен позже (вместе с [ADR-0010](0010-port-presentation-and-binding.md)) по той
же причине, по которой существуют первые три: свойство, которое проверяет только человек в
игре, проверяется редко и нестабильно. Границы, на которых это возможно, заданы слоями:
`Vgs.Model` и два геометрических типа не имеют ссылок на игру, поэтому их логика
исполняется без Space Engineers.

Правило можно подавить комментарием `// review:allow R0NN <причина>` на той же строке.
Подавление без причины — само по себе находка (R000): иначе шлюз перестают читать.

Шлюзы не заменяют ревью и не заменяют проверку в игре. Они снимают с них механическую
часть.

## Alternatives

| Вариант | Почему отклонён |
|---|---|
| Только запуск игры | Десятки минут на цикл вместо секунд |
| Только `dotnet build` по обычному csproj | Целится не в те сборки и не в тот framework; даёт ложные зелёные результаты |
| Ручной чеклист ревьюера | Нестабилен, зависит от внимания; идеально подходит для автоматизации |
| Фреймворк юнит-тестов для шлюза 4 | Внешний пакет, который мод не может поставить, и который пришлось бы ставить каждому агенту. `Main` с сравнениями и текстом утверждения решает ту же задачу |
| Гонять шлюз 4 через сам мод в игре | Дорого и не нужно: проверяемые типы специально не имеют игровых зависимостей |

## Consequences

- Легко: ошибка компиляции, нарушение слоя и разъехавшаяся геометрия находятся за секунды.
- Трудно: при смене версии игры меняются пути и набор ссылок — скрипты нужно сопровождать.
- Трудно: новое правило графа или геометрии требует утверждения в `tests/OfflineChecks.cs`;
  это намеренное трение, иначе правило остаётся непроверенным.
- Запрещено: сообщать о готовности изменения без зелёных `verify-compile` и
  `offline-check`.
- Ограничение: `verify-compile` проверяет только то, что мод вызывает, но не то, что он
  делает; `offline-check` проверяет только то, что не касается игры.

## Verification

```powershell
pwsh -File tools/verify-compile.ps1    # → COMPILE OK — 13 file(s), 0 warning(s)
pwsh -File tools/check-whitelist.ps1   # → WHITELIST OK
pwsh -File tools/review-check.ps1      # → REVIEW OK — no findings
pwsh -File tools/offline-check.ps1     # → OFFLINE OK — 123 checks
```

Все четыре должны завершаться успешно перед сдачей изменения.

### Шлюз сам проверяется

Правило, которое никогда не срабатывало, не работает. Каждое правило проверено двумя
способами:

- **положительно** — на реальных исходниках мода даёт 0 находок;
- **отрицательно** — на специально сломанном файле даёт ожидаемую находку.

Отрицательная проверка R001–R010 выполняется так: создать временный каталог с файлом,
нарушающим ровно одно правило, и запустить
`pwsh -File tools/review-check.ps1 -SourcePath <каталог> -Rules <R0NN>`.

Отрицательная проверка шлюза 4: скопировать `GridGraph.cs` с раздачей `port.Slot = 0`
всем портам и собрать шлюз на этой копии. Ожидаемо — `OFFLINE FAILED — 13 of 119 checks`
и код возврата 1 (проверено; на полном наборе утверждений — 123 проверки).

Эта процедура уже нашла дефект в самом шлюзе: `Get-Content` на файле из одной строки без
перевода строки возвращает скалярную строку, и `$lines[$i]` давал **символ**, а не строку —
однострочные файлы молча пропускались всеми правилами. Исправлено обёрткой
`@(Get-Content ...)`.
