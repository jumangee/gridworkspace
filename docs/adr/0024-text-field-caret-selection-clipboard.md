## Context

### 1. Что именно не работало

Поле поиска (ADR-0023) умело ровно одно: дописывать символы в конец строки. Не было каретки —
то есть нельзя было ни исправить символ в середине, ни поставить курсор кликом; не было
выделения — значит ни Ctrl+A, ни Shift+стрелок, ни замены всего запроса одним движением; не
было Ctrl+C/X/V.

### 2. Поле игры взять нельзя — это проверенный факт, а не догадка

[ПРОВЕРЕНО] `tools/find-se-type.ps1 -Name 'MyGuiControlTextbox*'` — поле существует:

```
Sandbox.Graphics  class  Sandbox.Graphics.GUI.MyGuiControlTextbox
```

но [ПРОВЕРЕНО] `tools/check-whitelist.ps1 -Dump` показывает, что `Sandbox.Graphics` **не
входит** в 57 разрешённых пространств имён (вайтлист перечисляет пространства точно:
`Sandbox.Game` разрешён, `Sandbox.Game.Screens.Helpers` — нет, и `Sandbox.Graphics` тоже нет).
Ссылка на это поле компилируется локально и отклоняется игрой при загрузке строкой
`The type or member 'MyGuiControlTextbox' is prohibited` — то есть мод не загрузится целиком.
Это ровно тот случай, ради которого в проекте есть второй шлюз ([ADR-0008](0008-mod-screen-api.md)).

Внутри `MyGuiControlTextbox` есть готовое `MyGuiControlTextboxSelection.PasteText` — то есть
игра такое умеет, но **не для мода**.

### 3. Буфер обмена: писать можно, читать нельзя

> **Неверно, заменено [ADR-0025](0025-clipboard-read-via-platform.md).** Читать можно, через
> `VRage.MyVRage.Platform.System.Clipboard`. Текст ниже оставлен как причина замены.

[ПРОВЕРЕНО] `tools/dump-se-api.ps1 -Types 'VRage.Utils.MyClipboardHelper' -IncludeNonPublic`:

```csharp
public static Void SetClipboard(String text)   // единственный член, только запись
```

`VRage.Utils` разрешён моду, поэтому **запись** в системный буфер доступна.

[ПРОВЕРЕНО] поиск по всем сборкам игры (`GetMethods` по `*Clipboard*`/`*Paste*`) даёт
единственные кандидаты на чтение:

| Тип | Метод | Почему не годится |
|---|---|---|
| `Sandbox.Graphics.MyClipboardService` | `GetText()` | сборка `Sandbox.Graphics` — не в вайтлисте |
| `VRage.Platform.Windows.Forms.MyClipboardHelper` | — | тип **public**, но пространство имён не в вайтлисте (уточнено в ADR-0025) |
| `Sandbox.Game.Gui.MyGuiControlTextbox+…Selection` | `PasteText` | движковый GUI, не в вайтлисте |

Вывод: **у мода нет способа прочитать системный буфер обмена.** Это ограничение платформы, а не
недоделка, и оно определяет решение.

### 4. Дефект рамки: измерен по пикселям, а не на глаз

Скриншот владельца продукта (811×80) разобран попиксельно: рамка поля лежит в строках 29–68,
заливка — 29–68, а в строке 69 остаются пиксели цвета рамки в столбцах 122–123 и 773–774 и
пиксели заливки в 124–772.

```
y=68: рамка 122..774 (сплошная нижняя планка)
y=69: рамка 122..123 и 773..774, заливка 124..772   ← «отростки»
```

Причина — не «толщина», а **совпадение краёв**: вертикальные планки рисовались во всю высоту,
то есть заканчивались ровно там же, где нижняя планка, а заливка — во весь прямоугольник.
Три отдельных четырёхугольника с одинаковой номинальной границей растеризуются независимо, и
их округления расходятся: высокий четырёхугольник дотянулся на строку ниже плоского.

## Decision

### 1. Своё поле, но его логика — в `Vgs.Model`

`Model/TextEditor.cs` держит текст, каретку и якорь выделения; всё, что решает, *каким станет
текст*, живёт там, а не в экране. Причина та же, что у `NodeStateFormat` и `BlockSearch`: это
единственная часть, которую можно проверить без игры, и единственная, где ошибка не падает, а
тихо портит введённое.

**Модель — каретка плюс якорь, а не «начало и длина».** Якорь — неподвижный конец выделения,
каретка — подвижный; выделение есть «каретка ≠ якорь». Так Shift+←/→ получается из одного
правила, и исчезает целый класс ошибок, где длина выделения становится отрицательной, потому что
игрок потянул в другую сторону. Без выделения они равны — одно сравнение вместо второго флага,
который может с ними разойтись.

### 2. Клавиши

| Клавиша | Действие |
|---|---|
| символ | вставка в каретку, заменяя выделение |
| Backspace / Delete | удалить выделение, иначе символ до / после каретки |
| ← / → | сдвиг каретки; без Shift выделение схлопывается к тому краю, куда идём |
| Shift + ← / → / клик | расширить выделение |
| Home / End | в начало / в конец |
| Ctrl+A | выделить всё |
| Ctrl+C | копировать выделение (или весь запрос, если ничего не выделено) |
| Ctrl+X | вырезать; **без выделения не делает ничего** — опустошать поле, которое игрок ещё читает, было бы неожиданно |
| Ctrl+V | вставить из системного буфера, при отказе — из собственного (ADR-0025) |
| Enter | к первому совпадению (как было) |
| Esc | сброс поиска, затем закрытие (как было) |

Порядок в обработчике важен: управляющие клавиши разбираются **до** потока символов, а поток
читается **всегда** и последним — иначе необработанный символ переживёт кадр и придёт дважды
(см. [api-terminal-search.md](../01-research/api-terminal-search.md) §2.2).

### 3. Буфер обмена: честная асимметрия

> **Проверено игрой и подтверждено:** читать системный буфер мод не может
> ([ADR-0027](0027-clipboard-is-own-buffer-only.md)). Промежуточный ADR-0025 утверждал обратное
> и был неверен — мод с этой реализацией не загрузился. Текст ниже описывает действующее
> поведение.

- **Копирование и вырезание** пишут в системный буфер (`MyClipboardHelper.SetClipboard`) **и** в
  собственный буфер сессии. То есть скопированный запрос можно вставить в любое другое
  приложение — это работает по-настоящему.
- **Вставка** берёт только собственный буфер: прочитать системный нельзя (§3 контекста).
  Формулировка для игрока: «вставить можно то, что скопировано в редакторе».
- Ошибка записи в системный буфер не показывается пользователю: собственный буфер уже обновлён,
  и для редактора копирование состоялось. Пишется `VgsLog.Throttled`.
- Буфер освобождается при выгрузке сессии: иначе следующий мир получил бы то, что копировали в
  предыдущем.

Вставка обрезает переводы строк и табы (таб → пробел): поле однострочное.

### 4. Отрисовка: раскладка отдельно, живопись отдельно

Позиции каретки и краёв выделения — это вызовы метрик шрифта, поэтому они считаются **при
изменении**, а не каждый кадр (`EnsureFieldLayout`), и кэшируются вместе с горизонтальной
прокруткой и срезом строки, который реально рисуется. В пути отрисовки остаются только чтения:
прямоугольник, строка, два сравнения.

Каретка мигает половиной периода `VgsConstants.CaretBlinkFrames` по счётчику кадров редактора, и
фаза **перезапускается на каждое редактирование** — иначе нажатие может попасть в тёмную половину
и выглядеть как «ничего не произошло».

Выделение рисуется под текстом полупрозрачной заливкой, края зажимаются в область текста, чтобы
не залезть на рамку при прокрутке.

### 5. Рамка: убрать совпадение краёв, а не подбирать толщину

- Вертикальные планки `Border`/`BorderClipped` рисуются **от внутреннего края верхней до
  внутреннего края нижней** (`[y+t, y+h-t]`), а не во всю высоту. Тогда любое округление,
  вытолкнувшее планку на строку вниз, попадает в полосу, которая уже закрашена тем же цветом, —
  и не видно.
- Появился `VgsScreenDraw.Panel` — заливка плюс рамка одним вызовом, где заливка **вставлена на
  половину толщины** рамки. Это единственное значение, которое неверно ни в одну сторону: при
  вставке меньше толщины край заливки всегда уходит *под* рамку (она рисуется после и
  перекрывает), а при вставке на полную толщину округление в другую сторону оставило бы щель
  между заливкой и рамкой — тонкую тёмную линию внутри контрола.

Поле поиска и все остальные рамки редактора получают исправление через `Border`; поле поиска
дополнительно использует `Panel`.

### 6. Запрет: не пытаться достать движковый GUI

Ни `MyGuiControlTextbox`, ни `MyGuiControlMultilineText`, ни `MyGuiManager` — не «попробовать и
посмотреть». Вайтлист читается из IL игры шлюзом, и ответ уже известен: запрещено.

## Alternatives

| Вариант | Почему отклонён |
|---|---|
| Взять `MyGuiControlTextbox` из игры | `Sandbox.Graphics` нет в вайтлисте: мод не загрузится («is prohibited»). Проверено `check-whitelist.ps1 -Dump` |
| Свой `MyGuiScreenBase` с полем | `Sandbox.Graphics`/`Sandbox.Game.Screens` запрещены; это уже отменённый [ADR-0001](0001-ui-stack.md) |
| Каретка без выделения (минимальный вариант) | Выделение нужно не только для копирования: Ctrl+A + печать заменяет запрос, Backspace/Delete работают по выделению, Shift+клик правит середину. Оно не зависит от буфера и работает полностью |
| Не делать Ctrl+C/X вовсе, раз вставка ограничена | Копирование работает в полную силу — наружу, в любое приложение. Отказываться от работающей половины незачем; ограничение касается только вставки и названо честно |
| Читать системный буфер через `MyClipboardService.GetText()` | Тип в запрещённой сборке; недоступен моду |
| Читать буфер через `VRage.Platform.Windows` | Тип internal |
| Держать в буфере обмена только системный буфер | Прочитать его нельзя, значит вставка не работала бы вообще |
| Подобрать толщину рамки/координаты «на глаз», чтобы отростки пропали | Совпадение краёв осталось бы, и дефект вернулся бы на другом разрешении или при другом DPI. Правится причина |
| Заливка на весь прямоугольник, рамка поверх | Заливка вылезает за внешний край рамки — это и есть наблюдавшийся дефект |

## Consequences

Что становится легко:

- поле ведёт себя как текстовое поле: клик ставит каретку, Shift+клик расширяет выделение,
  Ctrl+A и печать заменяют запрос;
- скопированный запрос уходит в системный буфер и вставляется в другие приложения;
- правило «каким станет текст» проверяется офлайн, без игры.

Чем платим:

- **вставка ограничена буфером редактора** — жёсткий предел API, названный в подсказке и в этом
  ADR. Игрок, скопировавший имя блока в блокноте, вставить его в поиск не сможет;
- **`TextEditor` — новый тип в `Vgs.Model`**, и в нём есть изменяемое состояние (текст, каретка,
  якорь). Это допустимо по [ADR-0007](0007-mutable-model-dtos.md) (модель — изменяемые носители),
  но требует дисциплины: экран не редактирует текст в обход `TextEditor`;
- **раскладка поля кэшируется** и обязана инвалидироваться на каждое изменение текста, каретки и
  ширины области. Забыть инвалидацию — значит получить каретку на старом месте; поэтому
  `_fieldLayoutValid = false` стоит рядом с каждым изменением, а не в одном «общем» месте;
- **новый `Panel`** в `VgsScreenDraw`: ещё одна пара «заливка + рамка», которую надо использовать
  вместо ручной пары `Rect`+`Border` там, где важна аккуратность края.

Что запрещено:

- ссылаться на движковый GUI для текстового ввода;
- обещать пользователю вставку из системного буфера;
- править геометрию рамки подбором координат вместо устранения совпадения краёв.

## Verification

Проверено до реализации (2026-11-23):

```powershell
# поле игры существует, но запрещено моду
& .\tools\find-se-type.ps1 -Name 'MyGuiControlTextbox*'
& .\tools\check-whitelist.ps1 -Dump          # Sandbox.Graphics отсутствует в списке

# буфер обмена: ЗАМЕНЕНО ADR-0025 — чтение доступно, действующие команды там.
# Строка ниже показывает, почему первая проверка ошиблась: дамп печатает DeclaredOnly
# и не предзагружает VRage.Platform.Windows.dll, поэтому GetClipboardText в нём не виден.
& .\tools\dump-se-api.ps1 -Types 'VRage.Utils.MyClipboardHelper' -IncludeNonPublic

# шлюзы проекта
& .\tools\verify-compile.ps1     # COMPILE OK
& .\tools\check-whitelist.ps1    # WHITELIST OK
& .\tools\review-check.ps1       # без находок
& .\tools\offline-check.ps1      # OFFLINE OK, включая секцию «text field editing»
```

Офлайн проверяется вся логика правки: вставка в середину, лимит длины, замена выделения,
Backspace/Delete с выделением и без, выделение в обе стороны (якорь vs каретка), схлопывание и
расширение стрелками, SelectAll и SelectedText, клипы индексов, многосимвольная вставка,
отказ правки (текст и каретка не меняются), вставка длиннее освободившегося места.

Геометрия рамки проверена **измерением**, а не рассуждением: скриншот разобран попиксельно
(§4 контекста) — до правки в строке 69 оставались пиксели рамки в столбцах 122–123 и 773–774.
После правки вертикальные планки заканчиваются на внутреннем крае нижней, то есть внутри уже
закрашенной полосы.

Человек в игре (без этого «работает» не считается):

1. Открыть схему, набрать `abc`, кликнуть между `a` и `b` — каретка встала туда; набрать `X` —
   получилось `aXbc`.
2. Каретка **видна** и мигает; после нажатия клавиши она сразу видима (не в тёмной фазе).
3. ← / → двигают каретку, Home / End — в начало и конец.
4. Shift+← и Shift+→ расширяют выделение в обе стороны; выделение видно как подсветка под текстом.
5. Shift+клик мышью расширяет выделение до указанного места.
6. Backspace при выделении удаляет всё выделение, а не один символ.
7. Ctrl+A выделяет весь запрос; печать заменяет его целиком.
8. Ctrl+C копирует; **вставить в блокнот Windows** — текст вставился (это проверяет запись в
   системный буфер).
9. Ctrl+X вырезает, Ctrl+V вставляет вырезанное обратно.
10. Ctrl+V после копирования в блокноте **не вставляет** — это ожидаемое ограничение, а не
    дефект (см. §Consequences).
11. Длинный запрос (больше ширины поля) прокручивается так, что каретка остаётся видимой.
12. Рамка поля: **нет «отростков»** под нижней гранью — ни по углам, ни по центру, ни при каком
    разрешении окна (проверить на 1920×1080, 2560×1440 и в оконном режиме произвольного размера).
13. Рамки остальных контролов (кнопка режимов, «Закрыть», меню, чекбокс) тоже без отростков —
    исправление общее для `Border`.
14. Ввод не управляет кораблём; Ctrl+A не «выделяет всё» в игре под экраном.
