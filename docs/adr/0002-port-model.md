# 0002. Модель портов: входы из API, выходы из таблицы

- Status: accepted
- Date: 2026-11-18
- Supersedes: —
- Amended by: [0010](0010-port-presentation-and-binding.md) — состав портов не меняется,
  меняется **направление уникальности**: входящий порт теперь может принимать несколько
  источников (fan-in). Здесь остаётся верным всё, что сказано об источнике данных портов.

## Context

Пользователь должен видеть у каждого блока его входы и выходы.

Проверено:

- **Входы** доступны: `IMyTerminalBlock.GetActions(List<ITerminalAction>, Func<...>)`
  возвращает реальный список действий блока, включая добавленные другими модами.
- **Выходы** недоступны. Обход всех экспортированных типов всех сборок `Bin64` не нашёл
  метода или свойства, возвращающего список событий блока. Существуют C#-события
  конкретных типов (`IMySensorBlock.StateChanged: Action<bool>`,
  `IMyEventControllerBlock.ActionTriggered: Action<int>`), но из них нельзя получить
  перечень «какие события бывают у сенсора» — только подписаться на известное заранее.

## Decision

Две половины, два разных механизма:

1. **Входы** читаются из API на этапе построения узла (`GridGraphBuilder.TryReadActions`)
   и больше не пересчитываются, пока набор действий не изменился.
2. **Выходы** берутся из курируемой таблицы `Vgs.Model.BlockPortCatalog`: семейство блока
   определяется по подстроке подтипа (`cockpit`, `battery`, `sensor`, …), к нему
   добавляется общий набор (`StateChanged`, `BlockAdded`, `BlockRemoved`,
   `IntegrityChanged`, `OnOffChanged`).

Неизвестный тип блока не остаётся пустым: он получает реальные входы и общий набор
выходов, а не пустую карточку.

На этапе 3 события будут **генерироваться** поллингом состояния с сравнением с предыдущим
значением; таблица отвечает на вопрос «что можно слушать», поллинг — «когда это произошло».

## Alternatives

| Вариант | Почему отклонён |
|---|---|
| Поллинг для отображения портов | Пользователь увидел бы порты только после того, как событие уже случилось; список был бы нестабильным |
| Рефлексия по типам игры для вывода событий | События C# не описывают семантику блока; результат был бы нестабильным между версиями и неполным |
| Жёсткий список подтипов вместо семейств | 1559 подтипов в каталоге игры; поддержка такого списка невозможна |

## Consequences

- Легко: входы всегда точные и работают для блоков других модов.
- Трудно: таблица выходов требует ручного пополнения; новый тип блока из другого мода
  получит только общий набор.
- Запрещено: обещать в UI выход, которого нет в таблице и который не генерируется
  поллингом.
- При ошибке меняется один файл `BlockPortCatalog.cs`.

## Verification

- `pwsh -File tools/dump-se-api.ps1 -Types 'Sandbox.ModAPI.Ingame.IMySensorBlock'` —
  подтверждает, что событие есть, а перечня событий нет.
- В игре: у кокпита, батареи, сенсора и таймера наборы выходов различаются; входы кокпита
  совпадают со списком действий в терминале.
