# 0037. Действие называется именем игры, а список действий показывает, что он длиннее окна

- Status: accepted
- Date: 2026-11-25
- Supersedes: — (уточняет §4a ADR-0002 и §4 ADR-0033)
- Joint review: —

## Context

Список действий в меню привязки — суть проекта: игрок выбирает им, что произойдёт с блоком.
Пользователь сообщил, что список **не отражает реальные действия**: у event controller и у
таймера он выглядел одинаково и заканчивался строками `Increase Font Size`, `Decrease Font
Size`, `Increase Text Padding Slider`, а вместо ожидаемых `Toggle block On/Off`,
`Show on HUD On`, `Silent On/Off`, `Trigger now`, `Start`, `Stop` показывал `On Off`,
`On Off_ On`, `Show On HUD`.

Разбор дал две независимые причины, и обе — наши.

**1. Подпись строилась из id, а не из имени.** `BlockPortCatalog.FillActions` вызывал
`Humanize(id)`, то есть расставлял пробелы в строке сохранения: `OnOff_On` → `On Off_ On`,
`IncreaseTextPaddingSlider` → `Increase Text Padding Slider`. Игра при этом уже имеет
локализованное имя для каждого действия, и это именно те строки, которые пользователь
ожидал увидеть. Проверено по сборкам установленной игры:

```powershell
& .\tools\dump-se-api.ps1 -Types 'Sandbox.ModAPI.Interfaces.ITerminalAction'
```

```csharp
public String Id { get; }                 // ключ сохранения: "OnOff_On"
public StringBuilder Name { get; }        // подпись: "Toggle block On"
```

Имя складывается из заголовка контрола и локализованного суффикса — это видно в
`MyTerminalControlExtensions.EnableOnOffActions` (заголовок + `" "` + `MyTexts.Get(ON/OFF)`),
а сам заголовок `OnOff` — строка `BlockAction_Toggle` = `Toggle block` в
`Content/Data/Localization/MyTexts.resx`:

```powershell
& .\tools\dump-se-il.ps1 -Assembly 'Sandbox.Game.dll' `
    -Type 'Sandbox.Game.Gui.MyTerminalControlExtensions' -Method 'EnableOnOffActions'
```

**2. Список обрезался молча.** Меню показывает не больше `ActionMenuMaxRows = 9` строк и
листается колесом, но ни счётчика, ни полосы прокрутки не рисовало. У event controller и
таймера девять видимых строк выглядели как весь список, а «лишние» три строки
(`Increase Font Size`, `Decrease Font Size`, `Increase Text Padding Slider`) — это седьмая,
восьмая и девятая строки **более длинного** списка, продолжение которого просто не было видно.

Что список действий **разных** блоков не может совпадать, проверено по IL: event controller
регистрирует `Toolbar`, `AvailableEvents`, `Condition`, `Threshold` (с `EnableActions`, то есть
`Increase/Decrease Threshold`), `SetThreshold`, `SearchBox`, `AvailableBlocks`,
`SelectBlocksButton`, `SelectedBlocks`, `RemoveBlocksButton`, `ANDCheckbox` (+ `EnableOnOffActions`),
и ничего про шрифт или картинки:

```powershell
& .\tools\dump-se-il.ps1 -Assembly 'SpaceEngineers.Game.dll' `
    -Type 'SpaceEngineers.Game.Entities.Blocks.MyEventControllerBlock' -Method 'CreateTerminalControls'
```

Строки `FontSize`, `TextPaddingSlider`, `ChangeIntervalSlider` живут в контролах панели
текста (`SpaceEngineers.Game.dll`, `MyMultiTextPanelComponent`/`MyTextPanel`), то есть
принадлежат LCD, а не контроллеру события. Значит, наблюдение «у event controller те же
действия, что у LCD» объясняется либо тем, что меню было открыто на карточке LCD, либо
чтением списка не у того блока — и второе обязано быть видно в логе, а не выясняться
догадками. Поэтому в том же изменении меню пишет строку `[VGS] action menu for <subtype>
(<entityId>): N action(s): <id>, <id>, …`.

## Decision

1. **Подпись порта-действия — имя игры.** `Vgs.Game` читает `ITerminalAction.Name` рядом с
   `Id` (одним проходом, в том же месте, где уже читается список действий), копирует его в
   `string` и передаёт в `Vgs.Model` параллельным списком:
   `BlockPortCatalog.FillActions(node, ids, names)`. `Humanize` остаётся запасным вариантом
   для действия, которое имени не сообщило, и основным для событий, которых игра не именует.
   Ключ порта по-прежнему `Id`: в сохранении и в тулбаре живёт id, а не подпись.
2. **У группы подписи берутся у участника, из списка которого пришёл id** — то есть у первого
   читаемого участника, потому что обе ветви правила идут по его спискам. `GroupMemberActions`
   получает `ActionNames`, параллельный `ActionIds`, а `ComputeGroupActionIds` заполняет
   второй выходной список. Групповой порт читается так же, как порт самого блока.
3. **Список действий показывает, что он длиннее окна.** Когда строк больше, чем помещается,
   меню рисует счётчик `1-9 / 15` в полосе заголовка и полосу прокрутки с ползунком справа.
   Счётчик форматируется при открытии меню и при прокрутке, а не в кадровом пути.
4. **Открытие меню пишется в лог** одной строкой: подтип блока, его entity id, число действий
   и сами id. Это единственный способ отличить «список не тот» от «карточка не та», не
   поднимая отладчик, и он же нужен в отчёте игрока.

## Alternatives

- **Оставить `Humanize` и добавить словарь id → русская строка.** Отклонено: словарь пришлось
  бы вести для каждого блока игры и каждого мода, он устаревал бы с каждым обновлением, и он
  повторял бы работу, которую игра уже сделала. Имя приходит из той же таблицы локализации,
  что и весь остальной терминал.
- **Брать подпись из `ITerminalAction.WriteValue` или из заголовка контрола.** Отклонено:
  `WriteValue` пишет *значение* (у слайдера — число), а заголовок контрола не содержит
  суффикса `On`/`Off`, который и различает три действия одного переключателя.
- **Хранить подпись в сохранении.** Отклонено: подпись зависит от языка игры, а ключ — нет.
  Сохранённая подпись замерла бы на языке, на котором схему создали.
- **Увеличить `ActionMenuMaxRows` и считать проблему решённой.** Отклонено: список любого
  блока конечен, а экран — нет; у проектора и LCD действий больше, чем влезает при любом
  разумном размере меню. Прокрутка уже была, не хватало признака, что она есть.
- **Показывать id вместо имени в подсказке.** Отклонено: игрок ищет в терминале и в тулбаре
  игру по имени, а не по id; id остаётся в логе и в сохранении, где он и нужен.

## Consequences

- Легко: список в редакторе и список в ванильном тулбаре читаются одинаково, и игрок узнаёт
  действие, которое уже видел в терминале. Группа и блок называют одно действие одинаково.
- Трудно: подпись теперь читается из игры, поэтому смена языка игры не переименовывает порты
  уже открытой схемы — порты перестраиваются только при изменении набора действий. Экран
  открывается заново при смене языка, так что на практике это не видно; но помнить об этом
  надо, и это записано здесь, а не выясняется потом.
- Запрещено: строить пользовательскую подпись действия из его id, если игра имя сообщила;
  рисовать список, обрезанный по `ActionMenuMaxRows`, без признака продолжения.
- Если решение окажется неверным (имя игры окажется не тем, что ждёт игрок): `FillActions`
  принимает имена списком, поэтому достаточно поменять то, что кладёт в него `Vgs.Game`;
  модель, граф и сохранения не трогаются.

В игре (человек):

1. Таймер → таймер: в меню `Toggle block On/Off`, `Toggle block On`, `Toggle block Off`,
   `Show on HUD …`, `Silent On/Off`, `Increase Delay`, `Decrease Delay`, `Trigger now`,
   `Start`, `Stop` — те же слова, что в терминале.
2. Тот же таймер: если строк больше девяти, в заголовке стоит `1-9 / N`, справа видна полоса
   прокрутки, колесо листает список до конца.
3. Event controller: в списке есть `Increase Threshold`, `Decrease Threshold`, `Set Threshold`
   и `AND …`, и **нет** ничего про шрифт, отступы текста или интервал смены картинки.
4. В логе после открытия меню — строка `[VGS] action menu for <subtype> (<id>): N action(s): …`
   с теми же id, что в списке.
