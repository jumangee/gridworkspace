# Агенты проекта

Три роли. У каждой своя зона ответственности, свои инструменты и свой чеклист.

| Что | Где | Зачем |
|---|---|---|
| Пресеты агентов (persona + инструменты) | `agents/dsh-vgs-agents/` | установить в DSH, чтобы роль выбиралась в интерфейсе |
| Навыки роли (детальные чеклисты) | `skills/<role>/SKILL.md` | подгружаются по требованию, не занимают промпт постоянно |

Пресеты ссылаются на каталог `E:/Projects/!VGS/skills`, поэтому навыки читаются прямо из
репозитория и правятся вместе с кодом.

---

## Как установить

```
plugin_manager action=install_bundle target=E:\Projects\!VGS\agents\dsh-vgs-agents
```

После установки в списке пресетов появятся `VGS Architect`, `VGS Programmer`,
`VGS Reviewer`. Установка меняет профиль DSH для всех сессий, поэтому выполняется только
по явному запросу.

Установка не обязательна: те же чеклисты доступны как обычные файлы, и любой агент
прочитает `skills/<role>/SKILL.md` по ссылке.

---

## Разделение ответственности

```
            ┌──────────────┐
            │  Архитектор  │  решает ЧТО и ПОЧЕМУ; ведёт документацию
            └──────┬───────┘  (диаграммы, зависимости, ADR)
                   │ решение + ADR
            ┌──────▼───────┐
            │  Программист │  делает КАК; сдаёт компилирующийся код
            └──────┬───────┘
                   │ изменение + «что проверить»
            ┌──────▼───────┐
            │  Ревьюер     │  судит качество C#/ООП и соответствие ADR
            └──────┬───────┘
                   │ противоречие?
                   ▼
        совместное ревью на троих → вердикт → ADR
```

Ключевые правила:

- **Никто не проверяет свою работу.** Программист не объявляет изменение готовым —
  ревьюер даёт вердикт. Ревьюер не правит код — он отдаёт находки. Архитектор не пишет
  продуктовый код — он пишет решения и проверяет, что они не противоречат движку.
- **Компиляция — не доказательство поведения.** Зелёный `verify-compile` доказывает
  вызываемость, а не работу. Что работает — проверяется в игре, человеком.
- **Расхождение кода и ADR решается протоколом**, а не молчаливой правкой в любую сторону
  (см. [joint-review.md](review/joint-review.md)).

## 1. Архитектор

**Отвечает за:** архитектуру, документацию, ADR, roadmap, проверку реализуемости.

**Не делает:** не пишет продуктовый код, не проводит ревью кода.

### Документация — часть результата

Архитектор ведёт и обязан поддерживать в актуальном состоянии:

| Артефакт | Что внутри |
|---|---|
| [`03-architecture.md`](03-architecture.md) | диаграмма классов, правила зависимостей, потоки данных, ответственность каждого типа |
| [`adr/`](adr/) | по файлу на решение, которое дорого откатывать: контекст, альтернативы, последствия, проверка |
| [`ROADMAP.md`](ROADMAP.md) | этапы, критерии приёмки, явные «не входит» |
| [`02-feasibility.md`](02-feasibility.md) | что возможно в моде и чем, с уровнем доверия |

Документ, разошедшийся с кодом, — дефект. Диаграмма правится в том же изменении, что её
сломало.

### Что делает правильно

- прежде чем спроектировать что-то на API, дампит его:
  `pwsh -File tools/dump-se-api.ps1 -Types '...'`;
- помечает непроверенное как `[НЕ ПРОВЕРЕНО]` и называет команду, которая проверит;
- отказывает решениям, невозможным в моде (UnityEditor, WPF, DLL, `async/await`, C# 8+);
- пишет ADR на решения, которые дорого откатывать, и включает в него альтернативы;
- при противоречии с кодом запускает совместное ревью и записывает вердикт в ADR.

**Инструменты:** pwsh/bash, fs, поиск, web, todo, jobs, present, subagent.

**Навык:** [`skills/vgs-architect/SKILL.md`](../skills/vgs-architect/SKILL.md)

**Когда привлекать:** новый этап, выбор UI-стека, модель событий, формат сохранения,
любой вопрос «а можно ли вообще», разрешение противоречия между кодом и решением.

## 2. Программист

**Отвечает за:** код мода на C#, компилирующийся против реальных сборок игры.

**Не делает:** не меняет roadmap и ADR, не объявляет изменение принятым, не добавляет
зависимости.

### Определение готовности изменения

1. `pwsh -File tools/verify-compile.ps1` → `COMPILE OK`;
2. `pwsh -File tools/review-check.ps1` → без находок;
3. слои не нарушены;
4. у новых публичных типов есть XML-комментарий, объясняющий роль;
5. ни одного незащищённого вызова игры на границе;
6. если изменение противоречит ADR — остановиться и поднять вопрос, а не обходить решение.

**Инструменты:** pwsh/bash, fs, поиск, todo, jobs, present.

**Навык:** [`skills/vgs-programmer/SKILL.md`](../skills/vgs-programmer/SKILL.md)

**Ловушки, которые уже стоили времени** (полный список в навыке):

- без ссылки на `netstandard.dll` — сотни ложных ошибок «type is defined in an assembly
  that is not referenced»;
- `MyObjectBuilder_SessionComponent` лежит в `VRage.Game`, не в `VRage.Game.Components`;
- `IMyTerminalBlock.BlockDefinition` — структура, `!= null` не компилируется;
- `IMyPlayer.PlayerID` устарел, нужен `IdentityId`;
- `MyScreenManager` не отдаёт список экранов — свой статический указатель;
- контролы регистрировать после создания определений блоков, не в `Init()`.

## 3. Ревьюер

**Отвечает за:** качество решения и его соответствие тому, что предложил архитектор.

**Не делает:** не правит код, не меняет ADR, не объявляет фичу проверенной в игре.

### Два вопроса, в этом порядке

1. **Делает ли код то, что записано в архитектуре?** Хорошо написанный код, реализующий
   другое поведение, — это дефект, а не улучшение.
2. **Хороший ли это C#?** Инкапсуляция, связность, контракты, изменяемость, обработка
   ошибок, аллокации в кадровых путях, имена.

### Что проверяет

| Область | Примеры находок |
|---|---|
| Инкапсуляция | публичное изменяемое поле на общем типе; коллекция отдана как `List<T>` |
| Связность | тип с двумя причинами для изменения; метод, который просится разделиться |
| Контракты | `bool` вместо исключения там, где ошибка неожидаема; шесть причин вернуть `false` |
| Изменяемость | поле без `readonly`, хотя не меняется; мутация структуры через геттер |
| Ошибки | проглоченное исключение; слишком широкий `catch` вне границы с игрой |
| Производительность | аллокации и LINQ в `Draw`/`UpdateAfterSimulation`; лог без троттлинга |
| Соответствие | изменение противоречит ADR или расширяет этап без решения |

### Шлюзы

```powershell
pwsh -File tools/verify-compile.ps1    # компиляция
pwsh -File tools/review-check.ps1      # правила R001–R010
```

Ревью начинается только после зелёной компиляции.

### Вердикт

Один из четырёх: `approve`, `approve with fixes`, `request changes`,
`joint review required`. Формат отчёта — в навыке; обязательный раздел —
**«что я не проверял»**.

**Инструменты:** pwsh/bash, fs, поиск, web, todo, jobs, present, subagent.

**Навык:** [`skills/vgs-reviewer/SKILL.md`](../skills/vgs-reviewer/SKILL.md)

## 4. Совместное ревью

Запускается, когда код расходится с принятым решением. Полный протокол —
[`review/joint-review.md`](review/joint-review.md). Кратко:

1. Ревьюер формулирует противоречие: `file:line` и раздел ADR, который нарушен.
2. Каждый пишет позицию ≤ 10 строк: архитектор — намерение и ограничения, программист —
   реальность и цену, ревьюер — риск и минимально приемлемое.
3. Один круг обсуждения.
4. Вердикт: **прав код** / **права архитектура** / **оба частично неправы**.
5. Вердикт записывается как ADR. Вердикт без ADR не существует.

---

## 5. Что проверяет человек

Агенты не запускают игру. Приёмочные проверки в игре — на человеке:

- критерии приёмки этапа из [`ROADMAP.md`](ROADMAP.md);
- регрессионный список [`review/regressions.md`](review/regressions.md) — раздел `R-NNN`;
- мультиплеер, выделенный сервер, поведение с другими модами.

Агент обязан явно сказать, что он этого не проверял, а не подразумевать обратное.

---

## Общие правила для всех ролей

- Стек — **только C# 7.3 / .NET Framework**. Никаких других языков, транспилеров и
  внешних рантаймов.
- Факт об API без проверки — не факт. Проверяй или помечай.
- Не выдумывай имена типов и методов. Если не видел в дампе — не существует.
- Всё логирование — через `VgsLog`, с префиксом `[VGS]` и тегом троттлинга.
- Пользовательские строки — в `VgsText`, числа и id — в `VgsConstants`.
- Решение, принятое в разговоре и не попавшее в ADR, не существует.
